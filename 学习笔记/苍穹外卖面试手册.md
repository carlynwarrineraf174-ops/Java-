## 1. 项目速览（面试前 5 分钟看这一节）

### 1.1 一句话介绍

> 这是一个**餐饮外卖 SaaS 后台**：管理端（商家）管菜品/套餐/订单/员工/报表，用户端（微信小程序）浏览下单支付。后端 Spring Boot 单体应用，Maven 三模块分层，MySQL 存业务数据，Redis 存店铺状态与套餐缓存，WebSocket 给管理端推"来单提醒"，POI 导出运营报表，支付对接微信支付 V3。

### 1.2 模块与分层

```
sky-take-out（父工程）
├── sky-common   通用：Result / BaseContext(ThreadLocal) / 常量 / 异常 / 工具(JwtUtil, AliOssUtil, WeChatPayUtil, HttpClientUtil)
├── sky-pojo     数据：entity(表) / dto(入参) / vo(出参) / （部分项目含 POJO 转换）
└── sky-server   主程序：controller(admin/user/notify) · service · mapper · config · interceptor · aspect · annotation · handler · task · websocket
```

依赖方向：`server → pojo/common`，pojo 与 common 互不依赖。

## 2. 面试题汇总（32 题）

> 用法：先自己答，再看答案。带 🎯 的是**会被追问的第二层**。

### 一、项目与架构

**Q1. 介绍一下这个项目。**
外卖 SaaS 后台，两个端：管理端（商家）和用户端（小程序）。后端 Spring Boot 单体 + Maven 三模块（common/pojo/server），分层 Controller→Service→Mapper。技术点：JWT 无状态鉴权、AOP 自动填充公共字段、PageHelper 分页、Redis 缓存套餐与店铺状态、WebSocket 来单提醒、POI 导出运营报表、微信支付 V3、阿里云 OSS 存图。
🎯 追问：为什么不做微服务？答：业务体量小，单体更好维护；我另外用 Spring Cloud 做过微服务拆分（Nacos+Gateway+OpenFeign），知道拆分边界（按业务域拆、独立库、远程调用替代本地调用）。

**Q2. 三模块怎么划分的？**
`sky-common` 放跟业务无关的技术组件（Result、BaseContext、常量、异常基类、JwtUtil/AliOssUtil/WeChatPayUtil）；`sky-pojo` 放数据载体（entity 对应表、dto 接请求、vo 回响应）；`sky-server` 是主程序，装所有业务代码。依赖方向单向：server → pojo/common。
🎯 追问：entity/dto/vo 区别？entity=表结构映射；dto=前端入参（可能含校验、组合字段）；vo=返回前端的裁剪/组装结果（如 EmployeeLoginVO 带 token、不带密码）。

**Q3. 统一返回结果怎么设计的？**
`Result<T>{code, msg, data}` + 静态方法 `success()/error()`；分页统一用 `PageResult{total, records}`。
🎯 追问：为什么不用 `PageInfo`？`Page`/`PageInfo` 会把 pageNum/pageSize/pages/navigatepageNums 等一堆内部字段序列化给前端，接口契约不稳定；`PageResult` 只暴露前端真正需要的两个字段。

**Q4. 全局异常怎么处理的？**
`@RestControllerAdvice` + `@ExceptionHandler`：`GlobalExceptionHandler` 接 `BaseException`（业务异常基类）返回 `Result.error(msg)`，另外单独接 `SQLIntegrityConstraintViolationException` 把"用户名重复"翻译成中文提示。业务层只管 `throw`，不用 try-catch。
🎯 追问：为什么业务异常都继承 RuntimeException？① 事务默认只对 RuntimeException 回滚；② 不用在方法签名上写 throws，代码干净。

### 二、鉴权与登录

**Q5. 登录鉴权怎么做的？**
JWT 无状态方案：登录成功用 `JwtUtil.createJWT(secretKey, ttl, claims)` 签发（claims 里放 empId/userId，HS256 签名）→ 前端存 token，之后每次请求放请求头（管理端 `token`、用户端 `authentication`）→ 拦截器 `JwtTokenAdminInterceptor` 验签解析 → `BaseContext.setCurrentId(id)` 存 ThreadLocal → 业务层随时取当前用户。
🎯 追问：JWT 和 Session 的区别？
| | JWT | Session |
|---|---|---|
| 存储 | 客户端（token） | 服务端（内存/Redis） |
| 扩展性 | 无状态，天然支持水平扩展 | 需要 Session 共享（Redis） |
| 主动失效 | ❌ 麻烦（要黑名单/双 token） | ✅ 删了就行 |
| 体积/安全 | payload 可被 base64 解码，不能放敏感信息 | 数据在服务端更安全 |

**Q6. 为什么用 ThreadLocal 存当前用户？**
避免"每个方法都传 userId"这种参数穿透。`BaseContext` 用 `ThreadLocal<Long>`，拦截器 set、Mapper 切面 get，同一请求在同一线程内共享。
🎯 追问：有什么风险？① **线程池复用会导致数据串号**，必须 `afterCompletion` 里 `remove()`（本项目**没做**，见坑 P1-1）；② **异步/回调线程取不到**（本项目支付回调就踩了，见坑 P0-1）。

**Q7. 管理端和用户端怎么隔离的？**
两套密钥（`admin-secret-key` / `user-secret-key`）、两个 token 字段名（`token` / `authentication`）、两个拦截器（各自 `addPathPatterns`），所以管理端 token 拿不到用户端接口。

**Q8. 哪些路径要放行？为什么？**
`/admin/employee/login`（登录时还没有 token）、用户端 `user/shop/status`（未登录也要看店铺是否营业）、`/doc.html` 等静态资源、`/notify/**`（微信服务器回调，没有 token）。
🎯 追问：不小心拦了会怎样？`/error` 被拦会导致"错误信息变成 401 且 body 为空"，排查半天（黑马点评里踩过）。

**Q9. 密码怎么存的？**
`DigestUtils.md5DigestAsHex(password.getBytes())`，存 32 位 MD5，登录时把明文 MD5 后比对。
🎯 追问：这样安全吗？**不安全**：MD5 无盐可查彩虹表、可暴力破解。生产做法：`BCryptPasswordEncoder`（自带随机盐 + 可调强度），或至少 `MD5+固定盐+多次哈希`。项目里为了教学简化了，我知道差异（这是坑 P2-1）。

### 三、AOP 与注解

**Q10. 项目里的 AOP 用在哪？**
`@AutoFill` 自动填充公共字段：`create_time/create_user/update_time/update_user`。自定义注解 + 切面，业务代码零侵入。
🎯 追问：不用 AOP 行不行？可以但很差：① 每个 insert/update 手写 2-4 行，几十处重复；② 漏了就写 NULL；③ 规则一变要改几十处。也可以用 MyBatis 拦截器或数据库默认值，但：数据库默认值拿不到"当前登录用户"，MyBatis 拦截器拿不到 `OperationType` 语义，AOP + 自定义注解最直观。

**Q11. 写一下切面的核心逻辑。**
```java
@Pointcut("execution(* com.sky.mapper.*.*(..)) && @annotation(com.sky.annotation.AutoFill)")
public void autoFillPointCut() {}

@Before("autoFillPointCut()")
public void autoFill(JoinPoint joinPoint) {
    MethodSignature sig = (MethodSignature) joinPoint.getSignature();
    OperationType type = sig.getMethod().getAnnotation(AutoFill.class).value(); // ① 读注解
    Object entity = joinPoint.getArgs()[0];                                     // ② 拿实体（约定第一个参数）
    LocalDateTime now = LocalDateTime.now();
    Long uid = BaseContext.getCurrentId();                                      // ③ 从 ThreadLocal 拿当前用户
    if (type == OperationType.INSERT) {                                          // ④ 反射赋值
        entity.getClass().getDeclaredMethod("setCreateTime", LocalDateTime.class).invoke(entity, now);
        entity.getClass().getDeclaredMethod("setCreateUser", Long.class).invoke(entity, uid);
        // ... updateTime / updateUser 同理
    } else if (type == OperationType.UPDATE) { /* 只填 update 两个 */ }
}
```
🎯 追问：为什么用反射？切面要"通用处理所有实体"（Employee/Category/Dish/Orders…），编译期不知道具体类型，只能运行时按方法名找 setter。

**Q12. `@Target` 和 `@Retention` 什么用？**
`@Target(ElementType.METHOD)` 限定只能标注在方法上（编译器检查）；`@Retention(RUNTIME)` 让注解保留到运行期，AOP 才能靠反射读到（SOURCE 编译后就丢、CLASS 只在字节码里但反射读不到）。

**Q13. AOP、拦截器、Filter 有什么区别？**
| | Filter | Interceptor | AOP |
|---|---|---|---|
| 规范 | Servlet | Spring MVC | Spring |
| 作用对象 | 所有请求 | Controller 方法 | 任意 Bean 方法 |
| 能否拿到方法参数/注解 | ❌ | ✅（HandlerMethod） | ✅（JoinPoint） |
| 典型用途 | 编码、跨域 | JWT 登录校验 | 事务、日志、自动填充 |
| 执行顺序 | 最外层 | 中间 | 最内层（方法级） |
本项目三者都有：Filter（编码）→ Interceptor（JWT）→ AOP（@AutoFill / @Transactional）。

### 四、事务

**Q14. 项目里哪里用了事务？为什么？**
`OrderServiceImpl.submitOrder`：订单表 insert + 明细表批量 insert + 清空购物车，三步必须原子，否则会出现"有订单没明细"的脏数据。`DishServiceImpl`/`SetmealServiceImpl` 的"主表 + 关联表"操作同理。

**Q15. `@Transactional` 什么情况会失效？（本项目口径）**
① **同类内部方法自调用**（没走代理，最常见）；② 方法**不是 public**；③ 异常被 **try-catch 吞掉**（没冒泡出去就不回滚）；④ 抛的是**检查异常**且没配 `rollbackFor`（默认只回滚 RuntimeException）；⑤ **`@Async`/新起线程**里执行（事务上下文不跨线程）；⑥ 大事务/传播级别配错（如 `REQUIRES_NEW` 用错会挂起外层事务、多占连接）。
🎯 追问：怎么验证事务真的生效？开 `logging.level.com.sky.mapper=debug` 看 SQL，或在方法里打印 `TransactionSynchronizationManager.isActualTransactionActive()`。

**Q16. 事务的隔离级别和传播行为？**
MySQL 默认 **REPEATABLE READ**（InnoDB 靠 MVCC + 间隙锁基本避免幻读）；本项目没改默认，也没改传播行为，全用 `REQUIRED`（有事务就加入，没有就新建）。

**Q17. 下单时并发重复提交会怎样？**
`submitOrder` 会先查购物车，空则抛 `ShoppingCartBusinessException`；但两次请求同时进来仍可能都读到非空 → 生成两笔订单（本项目没做幂等）。生产做法：① 前端按钮置灰 + 令牌（防重 token）；② 数据库唯一索引（如 `user_id + 购物车版本号`）；③ Redis 分布式锁按 userId 加锁；④ MQ 幂等消费。

### 五、MyBatis 与分页

**Q18. `#{}` 和 `${}` 的区别？**
`#{}` 是预编译占位符（→ JDBC `?`），安全、防注入，**传值永远用它**；`${}` 是字符串拼接，有注入风险，只在拼**表名/列名/排序字段**这种"不能当参数"的地方用（如 `order by ${sortColumn}` 需自己做白名单校验）。

**Q19. Mapper 接口为什么没有实现类？**
MyBatis 启动时用 **JDK 动态代理**给 `@Mapper` 接口生成代理对象（`MapperProxy`），调用接口方法时按 `namespace + id` 找到 XML 里的 SQL 或注解 SQL 执行。所以 Spring 注入的是一个代理 Bean。

**Q20. 动态 SQL 用了哪些标签？**
`<where>`（自动去掉多余的 and）、`<if test="...">`（条件拼接，OGNL 表达式）、`<set>`（update 自动去尾逗号，实现"只更新非空字段"）、`<foreach>`（`order_detail` 批量插入，一条 SQL 插 N 行，比循环单插快得多）。
🎯 追问：XML 里写 `>` `<` 要转义成 `&gt;` `&lt;`。

**Q21. 主键回填怎么做的？**
`<insert useGeneratedKeys="true" keyProperty="id">`：插入后把自增主键写回 Java 对象的 id。`submitOrder` 里必须靠它——先插 `orders` 拿到 id，再给每条 `order_detail` 设置 `orderId`，否则明细关联不上主订单。

**Q22. 分页怎么实现的？（**必答**）**
用 **PageHelper**：`PageHelper.startPage(pageNum, pageSize)` 把分页参数放进 **ThreadLocal**，MyBatis 拦截器 `PageInterceptor` 在查询时读出来 → 自动执行一次 `count` → 改写 SQL 加 `limit`。返回的 List 实际是 `Page<E>`（ArrayList 子类，带 total），再用 `new PageResult(page.getTotal(), page.getResult())` 转成统一结构。
🎯 追问：坑？`startPage` 之后**必须紧跟**要分页的查询，中间不能插入其他查询（ThreadLocal 参数会被消耗/错位）；`PageHelper.clearPage()` 可用于显式清理。详见第 4.2 节。

### 六、Redis 与缓存

**Q23. Redis 在本项目用在哪？**
① `SHOP_STATUS` 存店铺营业状态（管理端改、用户端读）；② 用户端套餐列表 `@Cacheable(cacheNames="setmealCache", key="#categoryId")`。

**Q24. 缓存怎么保证一致？**
管理端改套餐时 `@CacheEvict(cacheNames="setmealCache", allEntries=true)` 全删，下次查询重建。属于 **Cache Aside**（写库 + 删缓存）。
🎯 追问：为什么 allEntries 全删而不是按 key 删？因为套餐与分类的关联改动影响面不确定（改一个套餐可能影响多个分类的列表），全删简单且该缓存数据量小、重建便宜；数据量大时应按 key 精确删。

**Q25. 为什么用 Spring Cache 注解而不是手写 RedisTemplate？**
注解省掉样板代码、缓存穿透/击穿的统一处理留给框架；本项目场景简单（查多改少、允许短暂不一致）所以够用。手写能控制 TTL、空值缓存、逻辑过期（我在黑马点评里手写过 `CacheClient` 处理穿透/击穿）。

### 七、订单与支付

**Q26. 订单状态是怎么流转的？**
见 1.6 状态机。每个推进方法都**先查当前状态再判断**（如接单必须 status=2，取消必须未完成），状态常量用 `Orders.PENDING_PAYMENT` 而不是裸写 1。

**Q27. 支付怎么对接的？**
微信支付 **V3**：`WeChatPayUtil.pay()` 用商户私钥签名请求 → 拿 `prepay_id` → 返回签名参数给小程序调起支付 → 用户支付后微信回调 `/notify/paySuccess` → `AesUtil` 用 `apiV3Key` **AES-GCM 解密**回调报文 → 取 `out_trade_no` → 改订单状态 + WebSocket 提醒 → 回 `{"code":"SUCCESS"}`。

**Q28. 支付回调要注意什么？（**高频追问**）**
① **幂等**：微信会重复通知（失败重试，最多 8 次/24h），必须判断订单已支付就直接返回 SUCCESS；② **验签**：V3 要求用微信平台证书验 `Wechatpay-Signature`，**本项目只做了解密没验签**（见坑 P0-2）；③ **上下文**：回调不是用户请求，**没有 ThreadLocal 用户上下文**（见坑 P0-1）；④ **加锁/事务**：改状态要幂等，建议按订单号加锁。

**Q29. 退款怎么做的？**
三处：用户取消订单 `userCancelById`、商家拒单 `rejection`、商家取消 `cancel` —— 都先判断 `payStatus == PAID` 才调 `WeChatPayUtil.refund()`，成功后把 `payStatus` 改成 REFUND。

### 八、报表、文件与工程

**Q30. Excel 报表导出怎么做的？**
用 **POI 的 XSSFWorkbook** 读 `template/运营数据报表模板.xlsx` → 按坐标填概览（`getRow(1).getCell(1)`）+ 循环填明细 → `excel.write(response.getOutputStream())` → 关流关工作簿。数据来自 4 个统计接口（营业额/用户/订单/Top10）。
🎯 追问：大数据量怎么办？XSSF 全内存，几十万行会 OOM → 用 **SXSSF**（滑动窗口流式写，只保留若干行在内存）；再大就异步导出（消息队列 + 下载中心）。

**Q31. 文件上传怎么做的？**
`CommonController.upload(MultipartFile file)`：取原始文件名后缀 → `UUID.randomUUID() + 后缀` 作对象名（**避免同名覆盖 + 防路径穿越**）→ `AliOssUtil.upload(bytes, objectName)` 传阿里云 OSS → 返回 URL 存库。
🎯 追问：有什么风险？**没做类型/大小校验**（可上传 jsp/html 等），生产要加白名单后缀 + 大小限制 + 内容类型校验（见坑 P2-2）。

**Q32. 定时任务做了什么？**
`OrderTask`：① 每分钟扫"待付款超 15 分钟"的订单自动取消；② 每天 1 点把"派送中超 1 小时"的订单置为已完成。用 `@EnableScheduling` + `@Scheduled(cron=...)`。
🎯 追问：集群下会怎样？**每个实例都会跑一遍**（重复执行）→ 生产要用分布式锁（Redisson）或分布式调度（XXL-JOB）；本项目单机部署所以没处理（见坑 P1-4）。

### 3.1 文件上传 + 阿里云 OSS

**场景**：管理端新增菜品/员工头像时要传图片，图片不能存应用服务器本地（多实例不共享、重启丢失、还占带宽），所以传 OSS。

**代码链路**（`CommonController` → `AliOssUtil`）：
```java
@PostMapping("/upload")
@ApiOperation("文件上传")
public Result<String> upload(MultipartFile file) {
    String originalFilename = file.getOriginalFilename();                    // ① 原始文件名（含后缀）
    String extension = originalFilename.substring(originalFilename.lastIndexOf("."));  // ② 取后缀
    String objectName = UUID.randomUUID().toString() + extension;            // ③ UUID 重命名★
    String filePath = aliOssUtil.upload(file.getBytes(), objectName);        // ④ 上传，返回访问 URL
    return Result.success(filePath);                                         // ⑤ URL 存库（dish.image）
}
```
**三个设计点**：
| 点 | 为什么 |
|---|---|
| `MultipartFile` | Spring MVC 把 `multipart/form-data` 请求体封装成该对象，`getBytes()` 拿字节、`getOriginalFilename()` 拿原名 |
| **UUID 重命名** | ① 防止同名覆盖；② 防止用户传 `../../etc/passwd` 这类路径穿越；③ 避免中文名/特殊字符 URL 编码问题 |
| 返回 URL 而不是文件 | 前后端分离下，后端只负责"存"，前端直接用 URL 展示（OSS 可配 CDN + 图片处理参数） |

**配置**：`OssConfiguration` 读 `sky.alioss.*`（endpoint / access-key-id / access-key-secret / bucket-name）构造 `AliOssUtil` 交给 Spring。
🎯 **面试可讲**：`MultipartFile` 默认超过 `spring.servlet.multipart.max-file-size` 会抛 `MaxUploadSizeExceededException`，要配大 + 前端限制；生产还要做后缀白名单和内容校验。

### 3.2 PageHelper 分页插件

**用法**（项目里 3 个 Service 都是这个套路）：
```java
// EmployeeServiceImpl.pageQuery
PageHelper.startPage(employeePageQueryDTO.getPage(), employeePageQueryDTO.getPageSize()); // ★ 只影响紧邻的这一次查询
Page<Employee> page = employeeMapper.pageQuery(employeePageQueryDTO);   // 返回的其实是 Page（ArrayList 子类）
long total = page.getTotal();                                           // 总记录数（插件额外查的 count）
return new PageResult(total, page.getResult());                         // 转成统一分页结构给前端
```

**原理（面试要能说清）**：
```
PageHelper.startPage()  → 分页参数塞进 ThreadLocal（PageMethod.setLocalPage）
        ↓
Mapper 查询被 PageInterceptor（MyBatis 插件）拦截
        ↓
① 先执行 count SQL 拿 total     ② 改写原 SQL 拼上 limit ?, ?     ③ 结果包装成 Page 对象
        ↓
用完清理 ThreadLocal
```
🎯 **两个易错点**：
- `startPage()` 之后**必须紧跟**要分页的那次查询，中间插入别的查询会导致参数被误用；
- 返回类型声明成 `List<T>` 也能用，但只有接成 `Page<T>` 才能拿到 `getTotal()`。

### 3.3 Excel 报表导出（Apache POI）

**场景**：管理端"数据统计 → 导出 Excel"，把营业额/订单/用户等统计结果按**固定格式模板**导出。

**代码链路**（`ReportController.export` → `ReportServiceImpl.exportBusinessData`）：
```java
public void exportBusinessData(HttpServletResponse response) {
    // ① 读取模板：resources/template/运营数据报表模板.xlsx（表头、样式、合并单元格都做好了）
    InputStream in = getClass().getClassLoader()
            .getResourceAsStream("template/运营数据报表模板.xlsx");
    XSSFWorkbook excel = new XSSFWorkbook(in);       // ② 加载工作簿（XSSF = .xlsx，全内存）

    XSSFSheet sheet = excel.getSheet("Sheet1");      // ③ 取工作表
    sheet.getRow(1).getCell(1).setCellValue("时间：" + begin + "至" + end);  // ④ 按坐标填概览
    XSSFRow row = sheet.getRow(3);
    row.getCell(2).setCellValue(businessDataVO.getTurnover());              // 营业额
    row.getCell(4).setCellValue(businessDataVO.getOrderCompletionRate());   // 完成率
    row.getCell(6).setCellValue(businessDataVO.getNewUsers());              // 新增用户

    for (int i = 0; i < list.size(); i++) {                                 // ⑤ 循环填明细（每行一天）
        BusinessDataVO d = list.get(i);
        row = sheet.getRow(7 + i);                                          // ★ 坐标 = 起始行 + i
        row.getCell(1).setCellValue(d.getDate().toString());
        row.getCell(2).setCellValue(d.getTurnover());
        // ... 订单完成率 / 客单价 / 新增用户
    }

    ServletOutputStream out = response.getOutputStream();                    // ⑥ 用响应输出流写回浏览器
    excel.write(out);
    out.close();
    excel.close();
}
```

**四个必答点**：
| 点 | 说明 |
|---|---|
| 为什么用**模板** | 样式/表头/合并单元格在 Excel 里做好，代码只填数据；比用代码画样式省 90% 工作量 |
| `XSSFWorkbook` vs `HSSFWorkbook` vs `SXSSFWorkbook` | 分别对应 .xlsx（全内存）/ .xls（老格式、行数上限 65536）/ **流式 .xlsx（只留少量行在内存，大数据量必用）** |
| 为什么写 `HttpServletResponse` 输出流 | 导出是"文件下载"，不是 JSON；生产还要设 `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 和 `Content-Disposition: attachment;filename=xxx.xlsx` |
| 资源关闭顺序 | 先 `flush/close` 输出流，再 `close()` 工作簿；顺序反了可能写出不完整文件 |

🎯 **进阶**：数据量大要异步导出（提交任务 → MQ → 生成到 OSS → 通知下载），否则 HTTP 超时 + 内存爆。

### 3.4 微信支付 V3 + 支付回调

**支付流程（要能画）**：
```
① 用户点"去支付" → POST /user/order/payment
      └─ WeChatPayUtil.pay(订单号, 金额, 描述, openid)
            用商户私钥签名 → 调微信"JSAPI 下单"接口 → 拿 prepay_id
      └─ 把 prepay_id + 时间戳 + 随机串 + 签名 返回给小程序
② 小程序 wx.requestPayment(...) 调起微信收银台，用户输密码
③ 微信服务器异步回调 POST /notify/paySuccess（我们的 notifyUrl）
       body 是加密报文 → AesUtil(apiV3Key).decryptToString(...) 解密
       → 取 out_trade_no（商户订单号）、transaction_id（微信交易号）
       → orderService.paySuccess(outTradeNo)   ← 改状态 + 来单提醒
       → 响应 {"code":"SUCCESS","message":"SUCCESS"}（否则微信会重试）
④ 退款：WeChatPayUtil.refund()，用于 用户取消 / 商家拒单 / 商家取消
```

**回调必须处理的 4 件事**（本项目只做了前 1 件）：
| # | 要做的事 | 本项目现状 |
|---|---|---|
| 1 | **解密**报文取订单号 | ✅ 用 `AesUtil` 做了 |
| 2 | **验签**（校验 `Wechatpay-Signature`/`Wechatpay-Serial` 头，用微信平台证书） | ❌ **没做** → 任何人构造请求都能把订单改成"已支付"（坑 P0-2） |
| 3 | **幂等**（微信重复通知，判断订单已支付就直接返回 SUCCESS） | ❌ 没做（坑 P0-3） |
| 4 | **用户上下文**：回调不是用户请求，取不到 `BaseContext` | ❌ 现有实现依赖了它，导致 NPE（坑 P0-1） |

## 4. 难代码逐行精讲（附录 A）

### A1 · 支付回调 `paySuccess` —— 一个真实存在的 P0 缺陷 🎯

**现状代码**（`OrderServiceImpl.paySuccess`）：
```java
public void paySuccess(String outTradeNo) {
    Long userId = BaseContext.getCurrentId();                                  // ★ 问题 1
    Orders ordersDB = orderMapper.getByNumberAndUserId(outTradeNo, userId);    // ★ 问题 2
    Orders orders = Orders.builder()
            .id(ordersDB.getId())                                              // ★ 问题 3：NPE
            .status(Orders.TO_BE_CONFIRMED).payStatus(Orders.PAID)
            .checkoutTime(LocalDateTime.now()).build();
    orderMapper.update(orders);
    webSocketServer.sendToAllClient(json);   // 来单提醒 type=1
}
```
**问题链条**：
```
调用方是 PayNotifyController（微信服务器回调）
   → 该请求不经过 JwtTokenAdminInterceptor / JwtTokenUserInterceptor
   → BaseContext(ThreadLocal) 里没有值 → getCurrentId() 返回 null
   → getByNumberAndUserId(outTradeNo, null) 查不到 → ordersDB = null
   → ordersDB.getId() → NullPointerException
```
**为什么一直没被发现**：微信支付需要**真实商户号**，学习阶段基本都跳过支付（或只测下单不测支付），所以这条链路从没被触发。

**修复方案**：
```java
// ① OrderMapper 增加一个只按订单号查的方法
Orders getByNumber(@Param("orderNumber") String orderNumber);

// ② paySuccess 改造：不依赖登录上下文 + 幂等
public void paySuccess(String outTradeNo) {
    Orders ordersDB = orderMapper.getByNumber(outTradeNo);       // 不再用 BaseContext
    if (ordersDB == null) { log.error("订单不存在：{}", outTradeNo); return; }
    if (Orders.PAID.equals(ordersDB.getPayStatus())) {           // 幂等：微信会重复通知
        log.info("订单已支付，忽略重复通知：{}", outTradeNo);
        return;
    }
    Orders orders = Orders.builder().id(ordersDB.getId())
            .status(Orders.TO_BE_CONFIRMED).payStatus(Orders.PAID)
            .checkoutTime(LocalDateTime.now()).build();
    orderMapper.update(orders);
    // ③ 用订单里的 userId 而不是 ThreadLocal
    webSocketServer.sendToAllClient(buildNotifyJson(ordersDB));
}
```
**🎯 面试怎么讲**（这段是加分项）：
> "我在复盘支付链路时发现回调里取了 ThreadLocal 的当前用户，但回调是微信服务器发起的、不经过登录拦截器，所以那里必然是 null，只是因为没有商户号一直没触发。我把它改成了按订单号查询 + 支付状态幂等判断 —— 顺带解决了微信重复通知的问题。"

### A2 · PageHelper 的 ThreadLocal 与 SQL 改写

```java
public PageResult pageQuery(EmployeePageQueryDTO dto) {
    PageHelper.startPage(dto.getPage(), dto.getPageSize());   // ① 参数进 ThreadLocal
    Page<Employee> page = employeeMapper.pageQuery(dto);      // ② 被拦截器改写
```

**改写前后**：
```sql
-- 你写的
select * from employee
<where><if test="name != null"> and name like concat('%',#{name},'%') </if></where>
order by create_time desc
-- 插件实际执行两条
```

### A3 · POI 导出逐行（为什么这样写）

```java
InputStream in = getClass().getClassLoader().getResourceAsStream("template/运营数据报表模板.xlsx");
```
- 用 **ClassLoader 读 classpath 资源**（编译后 `target/classes/template/...`），不能用 `new File("src/main/...")`（打包成 jar 后路径不存在）。
```java
XSSFWorkbook excel = new XSSFWorkbook(in);
XSSFSheet sheet = excel.getSheet("Sheet1");
sheet.getRow(1).getCell(1).setCellValue(...);
```
- **坐标式写单元格**：`getRow(r)` 从 0 开始，`getCell(c)` 也从 0 开始 → `getRow(1).getCell(1)` 就是 Excel 里的 **B2**。
- 明细从 `getRow(7 + i)` 开始：模板前 7 行是表头和概览区，明细从第 8 行（index 7）开始往下填。
```java
ServletOutputStream out = response.getOutputStream();
excel.write(out); out.close(); excel.close();
```
- **写响应流**而不是返回对象：导出是文件下载语义；`XSSFWorkbook` 占用内存，必须 `close()` 释放（否则临时文件/内存泄漏）。
🎯 **改进点**：加 `response.setContentType(...)` 和 `Content-Disposition`；大数据量换 `SXSSFWorkbook`。

### A4 · AutoFillAspect 的三个设计决策

| 决策 | 代码体现 | 为什么 |
|---|---|---|
| 为什么切 **mapper 层**而不是 service 层 | `execution(* com.sky.mapper.*.*(..))` | 所有入库最终都走 mapper，切这里**覆盖最全**；切 service 会漏掉直接调 mapper 的地方 |
| 为什么用 `@Before` 而不是 `@Around` | `@Before("autoFillPointCut()")` | 只需要"执行前改参数"，不需要拦截返回值，`@Before` 更轻 |
| 为什么取 `args[0]` | `Object entity = joinPoint.getArgs()[0]` | 约定"实体永远是第一个参数"（项目里 insert/update 都符合），简洁；更严谨可按参数类型找 |
**🎯 追问：反射会不会慢？** 有开销但可忽略（相对一次 DB 往返），且 `getDeclaredMethod` 结果可以缓存；真正耗时的 JDBC 才是瓶颈。

### A5 · WebSocketServer 会话管理 + 集群改造

```java
@Component
@ServerEndpoint("/ws/{sid}")
public class WebSocketServer {
    private static Map<String, Session> sessionMap = new HashMap();   // ★ 静态：跨连接共享
    @OnOpen  public void onOpen(Session session, @PathParam("sid") String sid) { sessionMap.put(sid, session); }
    @OnClose public void onClose(@PathParam("sid") String sid) { sessionMap.remove(sid); }
    public void sendToAllClient(String message) {
        for (Session session : sessionMap.values()) {
            try { session.getBasicRemote().sendText(message); } catch (Exception e) { e.printStackTrace(); }
        }
    }
}
```
**为什么必须用 static**：`@ServerEndpoint` 标注的类，**每个 WebSocket 连接都会 new 一个实例**（不是单例 Bean），所以实例字段存不住"所有连接"，必须用静态集合。
**🎯 面试要点（现状 → 问题 → 改造）**：
| 现状 | 问题 | 改造 |
|---|---|---|
| `HashMap` 静态共享 | 多线程 put/remove 可能死循环/丢数据 | 换 `ConcurrentHashMap` |
| 单机内存 map | **多实例部署时只能推到本实例的连接**，管理端收不到别的实例的来单提醒 | Redis **Pub/Sub** 或 MQ 广播：每个实例订阅 `order:notify` 频道，收到后推给本地 session |
| `getBasicRemote().sendText()` 同步发送，无超时 | 慢客户端会**阻塞支付回调线程**（发送点就在 paySuccess 里！） | 用 `getAsyncRemote()` 异步发 + 设超时；或丢进队列异步广播 |
| `e.printStackTrace()` | 线上无法定位 | `log.error("ws 推送失败 sid={}", sid, e)` |

### A6 · JacksonObjectMapper 消息转换器

`WebMvcConfiguration.extendMessageConverters()` 里把自定义的 `JacksonObjectMapper` 塞进 `MappingJackson2HttpMessageConverter`，作用有两个：
1. **LocalDateTime 序列化成 `yyyy-MM-dd HH:mm:ss` 字符串**（默认会序列化成时间戳数组/ISO 格式，前端要额外处理）；
2. **反序列化时也按同样格式解析**（前端传时间字符串 → 后端 LocalDateTime）。
```java
// JacksonObjectMapper 里注册模块
JavaTimeModule module = new JavaTimeModule();
module.addSerializer(LocalDateTime.class, new LocalDateTimeSerializer(ofPattern("yyyy-MM-dd HH:mm:ss")));
module.addDeserializer(LocalDateTime.class, new LocalDateTimeDeserializer(ofPattern("yyyy-MM-dd HH:mm:ss")));
mapper.registerModule(module);
```
🎯 **追问：为什么不在每个字段上贴 `@JsonFormat`？** 全局配一次 vs 每个 VO 都贴，前者不侵入 POJO；缺点是不灵活（某些字段格式不同就要单独覆盖）。

## 5. 坑位大全（附录 B · 按严重程度分级）

> 🔇 = **静默错误**：不报错、能编译、能启动，但逻辑是错的 —— 最难查的一类。
> 每条的"面试怎么讲"就是你可以直接说的句子。

### P0 · 致命（数据错误 / 安全漏洞 / 服务不可用）

#### P0-1 🔇 支付回调里取 ThreadLocal 用户 → NPE
- **现象**：微信支付成功回调 `/notify/paySuccess` 抛 `NullPointerException`，订单永远停在"待付款"，但**微信那边显示支付成功**。
- **根因**：`paySuccess` 里 `BaseContext.getCurrentId()` 取当前用户，而回调是**微信服务器**发起的请求，不经过 JWT 拦截器，ThreadLocal 是空的 → `getByNumberAndUserId(outTradeNo, null)` 查不到 → `ordersDB.getId()` NPE。
- **✅ 正确写法**：回调链路里**只能按业务单号查**（新增 `getByNumber(outTradeNo)`），不能依赖登录上下文。
- **🎯 如何提前发现**：任何"非用户直接触发"的入口（回调、MQ 消费、定时任务、异步线程）都必须检查是否用了 `BaseContext`/`UserHolder`。
- **面试怎么讲**："我复盘支付链路时发现回调依赖了 ThreadLocal 用户上下文，但回调不走登录拦截器，那里必然是 null。我改成按订单号查询 —— 这也是为什么我在黑马点评里做异步秒杀时，要把 userId 打包进订单对象而不是在后台线程里取 ThreadLocal。"
- **详见**：第 4 节 A1（含完整修复代码）

#### P0-2 🔇 支付回调只解密不验签 → 可伪造支付
- **现象**：`PayNotifyController` 只从 body 里取 `resource.ciphertext` 做 AES 解密，**没有校验请求头里的 `Wechatpay-Signature` / `Wechatpay-Serial`**。
- **根因**：微信支付 V3 要求用**微信平台证书**对回调做验签，本项目省略了这一步。
- **危害**：任何知道 `notifyUrl` 的人，只要能构造出可解密的报文（或利用其它漏洞），就能把订单改成"已支付" —— 属于**资金安全漏洞**。
- **✅ 正确写法**：
```java
// 用微信支付 SDK 的验签器（WechatPay2Validator + 平台证书）先验签，再解密
if (!validator.validate(responseHeaders, body)) {
    response.setStatus(401); return;      // 验签失败直接拒绝
}
```
- **🎯 如何提前发现**：凡是"第三方回调"接口，先问三个问题：**怎么证明请求真的来自对方**（验签）、**重复发怎么办**（幂等）、**失败对方会重试吗**（响应格式）。

#### P0-3 🔇 支付回调没有幂等判断
- **现象**：微信重复通知时，`paySuccess` 会被反复执行（重复更新订单状态、重复推送来单提醒）。
- **根因**：微信在未收到 `SUCCESS` 响应时会**重试通知**（最多 8 次 / 24 小时），而代码里没判断"订单是否已支付"。
- **✅ 正确写法**：进方法先查订单，`payStatus == PAID` 就直接 `return`（并照样回 `{"code":"SUCCESS"}`，否则微信会一直重试）。
- **🎯 加分句**："幂等的通用做法有三种：状态机判断（本项目适用）、唯一索引（防重复插入）、去重表/Redis 记录已处理的消息 ID。"

#### P0-4 定时任务多实例重复执行
- **现象**：`@Scheduled` 在集群部署时，**每个实例都会跑一遍**（同时扫库、同时改状态、同时发提醒）。
- **✅ 正确写法**：① 用 Redis/Redisson 分布式锁（`tryLock` 包住任务体）；② 或换成分布式调度中心（XXL-JOB / ElasticJob）；③ 或把任务做成"抢占式"（`update ... where status=1 limit 1` 乐观锁）。
- **面试怎么讲**："单机没问题，但只要部署两个实例就会重复执行。这也是我在黑马点评里用 Redisson 做分布式锁的同一个问题域。"

### P1 · 严重（功能缺陷 / 隐藏风险）

#### P1-1 🔇 拦截器没有清 ThreadLocal（`BaseContext.remove()`）
- **现象**：`JwtTokenAdminInterceptor` / `JwtTokenUserInterceptor` 只 `setCurrentId`，**没有 `afterCompletion` 里 `remove()`**。
- **根因**：Tomcat 用**线程池**处理请求，线程会被复用。上一个请求留下的 userId 会残留在线程上；如果后续某个请求没走拦截器（放行路径、回调、异步任务），`getCurrentId()` 会拿到**上一个人的 id** → 数据串号（比如自动填充的 `update_user` 记错人）。
- **✅ 正确写法**：
```java
@Override
public void afterCompletion(HttpServletRequest req, HttpServletResponse resp,
                            Object handler, Exception ex) {
    BaseContext.removeCurrentId();   // 请求结束务必清理
}
```
- **🎯 如何提前发现**：凡是 `ThreadLocal`，搜索全项目有没有对应的 `remove()`；没有就是隐患。
- **面试怎么讲**："ThreadLocal 在线程池下必须显式清理，否则会内存泄漏 + 数据串号。这个项目只 set 没 remove，我补了 `afterCompletion` 清理。"

#### P1-2 🔇 RedisTemplate 只配了 key 序列化器
- **现象**：`RedisConfiguration` 里只有 `redisTemplate.setKeySerializer(new StringRedisSerializer())`，**value 仍是默认的 JDK 序列化**（`JdkSerializationRedisSerializer`）。
- **危害**：① 存到 Redis 的 value 是二进制乱码，`redis-cli` 看不懂、其它语言无法读；② 存的类必须实现 `Serializable`；③ 一旦改了序列化方式，**旧数据反序列化会失败**。
- **✅ 正确写法**：key 与 hashKey 用 `StringRedisSerializer`，value 与 hashValue 用 `GenericJackson2JsonRedisSerializer`（带类型信息，能直接反序列化成对象）；或者干脆用 `StringRedisTemplate` 手动 JSON。
- **跨项目联动**：这正是我在**黑马点评**里踩过的坑（默认 JDK 序列化导致 key 乱码），所以那边最后用了 `StringRedisTemplate` + 手动 JSON。

#### P1-3 文件上传没有类型/大小校验
- **现象**：`CommonController.upload` 只取后缀拼 UUID，**没校验后缀白名单、没校验文件内容、没限制大小**。
- **危害**：可上传 `.jsp/.html/.js` 造成存储型 XSS 或（若 OSS 配了自定义域名+解析）挂马；也可上传超大文件撑爆带宽/存储。
- **✅ 正确写法**：① 后缀白名单（jpg/jpeg/png/gif）；② 校验 `Content-Type` 与文件头魔数；③ 限制 `spring.servlet.multipart.max-file-size`；④ OSS 存桶设为"公共读但禁止执行"、图片走独立域名。
- **面试怎么讲**："上传接口是常见攻击面，我习惯做后缀白名单 + 魔数校验 + 大小限制三件套。"

#### P1-4 WebSocket 单机内存 map → 集群下管理端收不到提醒
- **现象**：`WebSocketServer` 用 `private static Map<String, Session>` 保存本机连接，`sendToAllClient` 只推给**本实例**的连接。
- **危害**：多实例部署时，用户支付回调可能落在实例 A，而管理端浏览器连的是实例 B → **收不到来单提醒**。
- **✅ 正确写法**：引入 **Redis Pub/Sub**（或 MQ 广播）：实例 A 把提醒消息 `publish` 到 `order:notify` 频道，所有实例订阅后各自推给本地 session。
- **🎯 底层原理**：`@ServerEndpoint` 的类**每个连接都会 new 一个实例**（不是单例），所以必须用 static 集合 —— 这点很多人答不上来。

#### P1-5 下单接口没有幂等/防重
- **现象**：`submitOrder` 只校验"购物车非空"，同一用户并发点两次会生成两笔订单。
- **✅ 正确写法**：① 前端按钮防抖 + 提交令牌；② 后端按 `userId` 加分布式锁；③ 数据库唯一索引兜底；④ 下单成功后清购物车（本项目有，但并发下不够）。

### P2 · 规范与优化

| # | 问题 | 建议 |
|---|---|---|
| P2-1 | 密码用 **MD5 无盐** 存储 | 换 `BCryptPasswordEncoder`（自带盐、可调强度） |
| P2-2 | `WebSocketServer` 用 **HashMap** 静态共享 | 换 `ConcurrentHashMap`（多线程 put/remove 不安全） |
| P2-3 | `sendToAllClient` 用**同步** `getBasicRemote()` + 无超时，且异常只 `printStackTrace()` | 改 `getAsyncRemote()`，异常用 `log.error`；发送点在支付回调线程上，慢客户端会拖慢回调 |
| P2-4 | WebSocket 里用 `System.out.println` | 换 `@Slf4j` 日志（线上无法查 System.out） |
| P2-5 | Excel 导出用 **XSSF（全内存）**，且未设 `Content-Type` / `Content-Disposition` | 大数据量换 `SXSSF`；补上响应头，否则浏览器可能直接打开而不是下载 |
| P2-6 | 敏感配置明文（`apiV3Key`、证书路径、数据库密码写在 yml/笔记里） | 敏感项走**环境变量**或配置中心；笔记里统一脱敏（我在 `Java学习笔记.md` 里也发现过明文数据库密码） |
| P2-7 | 事务粒度偏大（`repetition` 等也在事务里） | 只把"必须原子的多表写"放进事务，避免长事务占连接 |
| P2-8 | 缺参数校验（`@Valid` / `@NotNull`） | DTO 上加 JSR-303 校验，Controller 加 `@Validated`，由全局异常接住 `MethodArgumentNotValidException` |

### 6.3 三个可讲的难点（挑熟的两个讲）

**难点 1：公共字段自动填充（AOP + 自定义注解 + 反射）**
> "几十张表的 insert/update 都要填创建人/更新人。我用自定义注解 `@AutoFill(OperationType.INSERT)` 标在 Mapper 方法上，切面在方法执行前用反射调 setter 填值。难点在于：① 切面要通用，所以不能写死实体类型，只能反射；② 当前用户 id 要跨层拿到，靠拦截器 + ThreadLocal 传递；③ 得区分 INSERT 填 4 个字段、UPDATE 填 2 个字段。"

**难点 2：支付回调（幂等 + 验签 + 上下文）**
> "回调有三个坑：一是它不走登录拦截器，取不到 ThreadLocal 用户，我原实现里这里会 NPE，改成按订单号查询；二是微信会重复通知，我加了支付状态幂等判断；三是 V3 要求验签，我在方案里补了平台证书验签。这三件事其实是所有'第三方回调'的通用套路：**验签、幂等、响应格式**。"

**难点 3：运营报表导出**
> "报表要按固定格式导出，我用 POI 读提前做好的 Excel 模板，按坐标填概览和明细。这里要注意 classpath 资源用 ClassLoader 读、XSSF 是全内存要 close、大数据量得换 SXSSF 或者异步导出。数据来源是 4 个统计接口，SQL 上用了 `<where>` 动态拼接时间区间和聚合函数。"

### 6.4 高频追问速答（10 条）

| 追问 | 一句话应答 |
|---|---|
| 为什么不用 MyBatis-Plus？ | 项目用 XML 写动态 SQL 更可控；MP 我在别的项目用过（IService/条件构造器） |
| ThreadLocal 会不会内存泄漏？ | 会（key 弱引用 value 强引用 + 线程池复用），所以必须 remove，本项目我补了 |
| JWT 怎么实现登出？ | JWT 本身无状态不能主动失效；要么 Redis 存黑名单，要么双 token（access+refresh） |
| 为什么用 PageHelper 不自己写 limit？ | 省掉 count 查询和参数传递，且能和动态 SQL 无缝配合；缺点是隐式依赖 ThreadLocal |
| 事务里发 MQ/调远程接口行不行？ | 不建议，长事务 + 消息可能先于事务提交；用事务同步回调（`TransactionSynchronization`）或本地消息表 |

| 你这个项目有什么不足？ | 三个：① 单机 WebSocket 不支持集群；② 定时任务没有分布式调度；③ 支付回调的验签和幂等是我后来补的设计（见 6.5） |

### 6.5 "如果重做我会怎么改"（展示工程思维，面试官很吃这套）

1. **引入微服务拆分**：按业务域拆成商品/订单/用户/报表服务，用 Nacos 注册 + OpenFeign 调用 + Gateway 统一入口（我已经在用 Spring Cloud 做这件事）。

3. **支付链路加固**：验签 + 幂等 + 本地消息表（保证"改状态"和"发提醒"最终一致）。
4. **定时任务换 XXL-JOB**：解决集群重复执行 + 可视化 + 失败重试。
5. **WebSocket 换 Redis Pub/Sub 广播**：支持多实例。
6. **加可观测性**：接口耗时埋点、慢 SQL 告警、Docker + Nginx 部署脚本。
