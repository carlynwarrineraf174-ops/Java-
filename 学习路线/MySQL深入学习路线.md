## 2. 进阶篇：逐块要点（面试会怎么问）

### 🔥 索引三连（09-31，约 3.6 h 视频 / 10 h 跟敲）—— 全篇最高优先级

| 块 | 必须能答的问题 |
|----|--------------|
| 结构（09-17） | 为什么用 **B+ 树**而不是 B 树 / 哈希 / 红黑树？（磁盘 IO 次数 + 范围查询 + 树高） |
| 性能分析（18-21） | **explain 每个字段怎么读**：`type` 级别（system>const>eq_ref>ref>range>index>ALL）、`key_len` 怎么算、`Extra` 里 `Using filesort` / `Using temporary` / `Using index` 各意味着什么 |
| 使用规则（22-31） | 最左前缀、**索引失效 6 种情况**、覆盖索引与**回表**、前缀索引的取舍、单列 vs 联合索引、索引设计原则 |

> 🎯 **这一块的产出**：拿你**苍穹外卖 / 黑马点评的真实 SQL** 跑 explain，找出 3 条可优化的查询，
> 加索引后给出**前后耗时对比**（这就是简历上"优化过慢 SQL"的证据）。

### 🔥 锁（64-75，1.53 h / 4 h）—— 面试高频

- 全局锁（`FLUSH TABLES WITH READ LOCK`）→ 全库逻辑备份场景
- 表级锁：表锁 / **元数据锁 MDL**（DDL 与 DML 冲突）/ **意向锁**（IS/IX，解决"表锁与行锁的兼容判断"）
- 行级锁：**行锁**（锁索引项）、**间隙锁**（Gap，锁区间）、**临键锁**（Next-Key = 记录 + 前面的间隙）
- 🎯 必答：「**RR 级别下间隙锁怎么防幻读**」「**没有索引的更新会锁全表**」「**怎么排查死锁**（`SHOW ENGINE INNODB STATUS`）」

### 🔥 InnoDB + 事务 + MVCC（76-90，1.6 h / 4.5 h）—— 全篇最核心

| 块 | 必须能答 |
|----|---------|
| InnoDB 架构（76-80） | 内存结构（Buffer Pool / Change Buffer / Log Buffer）+ 磁盘结构（表空间/双写缓冲/redo）+ 后台线程 |
| 事务原理（81-83） | **redo log**（WAL、崩溃恢复、两阶段提交）+ **undo log**（回滚 + MVCC 版本链） |
| **MVCC（84-90）** | 隐藏字段（`trx_id`/`roll_pointer`）+ **undo log 版本链** + **ReadView**（`m_ids`/`min_trx_id`/`max_trx_id`/`creator_trx_id`）+ **RC 与 RR 的差别就在 ReadView 的生成时机** |

> 🎯 **这段话你必须能一口气讲出来**：
> "RR 和 RC 的区别不是隔离级别本身，而是 ReadView 生成的时机 —— RC 每次 SELECT 都生成新的 ReadView，
> 所以能看到别人提交的新数据（不可重复读）；RR 只在第一次 SELECT 生成，整个事务复用，所以可重复读。
> 幻读则靠间隙锁/临键锁挡住。"

### 👀 只看不敲（约 3.6 h 视频）

- **视图（40-44）**：知道"视图是虚拟表、能简化查询/限制列访问"，`WITH CHECK OPTION` 的 cascaded/local 区别（面试偶尔问）。**案例跳过**。
- **存储过程/函数（45-58）**：只看 45（介绍）、46（语法）、50（if）、51（参数 IN/OUT/INOUT）。
  🎯 面试话术："存储过程我了解，但生产项目里很少用 —— 因为它把业务逻辑下沉到数据库、难调试难版本管理，我们一般在应用层用 Service 组合 SQL。"
  **游标（21 min）、循环、handler 全部跳过**。
- **管理工具（91-94）**：只看 `mysqldump`（逻辑备份）、`mysqladmin`、`mysqlimport`。其余快过。

### ⏸ 直接跳过
Linux 版安装（18 min，你用 Windows/Docker）、触发器案例（59 介绍 3 min 看一眼即可）、各章小结、进阶篇总结。

## 4. ⚠️ 关键判断：MyCat 已过时，换 ShardingSphere

**为什么不学 MyCat（那 4.93 h 别浪费）**：

| 维度 | MyCat | ShardingSphere |
|------|-------|---------------|
| 定位 | **代理层**（独立部署一个"假 MySQL"） | **JDBC 层 + 代理层**（两种都有） |
| 生态 | 社区活跃度低，MyCat1.x 基本停更 | **Apache 顶级项目**，国内大厂主流选择 |
| 面试 | 问到会说"了解过，但项目里用的是 ShardingSphere" | **JDK 里写几行配置就能分库分表**，面试官更认 |
| 学习成本 | 装中间件 + 配一堆 XML | 加依赖 + 写 yml，**4 h 能跑通** |

**替代方案（4 h）**：
1. **ShardingSphere-JDBC 快速上手**（1.5 h）：引入依赖 + `application.yml` 配 `rules.sharding`
2. **分片策略**（1.5 h）：标准分片（`MOD`/`HASH_MOD`/`RANGE`）、**分片键选择**（为什么不能选会变的字段）、广播表/绑定表
3. **读写分离 + 广播表**（1 h）：`readwrite-splitting` 规则，主库写从库读
4. 🎯 面试必答：「**分片键怎么选**」「**跨库分页/聚合怎么办**」「**分片后 ID 怎么生成**（雪花算法）」「**扩容时数据怎么迁移**」

## 6. 必画的 5 张图 + 18 张问答卡

### 5 张图（白板 3 分钟能画完 = 过关）
1. **InnoDB 架构图**：内存（Buffer Pool / Change Buffer / Log Buffer / 自适应哈希）↔ 磁盘（表空间 / 双写缓冲 / redo / undo）
2. **B+ 树结构图**：非叶子只存索引 + 叶子成链表 + 一个节点一页 16KB → 三层能存约 2000 万行
3. **聚簇索引 vs 二级索引 + 回表**：主键索引叶子存整行，二级索引叶子存主键值 → 查非索引列要回表
4. **间隙锁/临键锁范围图**：给定 `id=5,10`，`WHERE id BETWEEN 6 AND 9` 锁住哪个区间
5. **MVCC 图**：版本链（`trx_id` + `roll_pointer`）→ ReadView 四个字段 → **RC 每次新生成 / RR 只生成一次**

### 18 张问答卡（按优先级）
① InnoDB vs MyISAM ② 为什么用 B+ 树 ③ 聚簇 vs 二级索引 ④ 回表与覆盖索引
⑤ 最左前缀法则 ⑥ 索引失效的 6 种情况 ⑦ 联合索引怎么设计 ⑧ 前缀索引取舍
⑨ explain 的 type/key_len/Extra 怎么读 ⑩ 全局锁/表锁/MDL/意向锁 ⑪ 行锁/间隙锁/临键锁
⑫ RR 怎么防幻读 ⑬ redo vs undo（WAL + 两阶段提交）⑭ binlog 三种格式 + 主从原理
⑮ **MVCC 原理 + RC/RR 差别** ⑯ 慢 SQL 排查流程 ⑰ 深分页 limit 怎么优化 ⑱ 大表怎么优化（分库分表/读写分离/归档）

## 7. 用你自己的项目做实验（这是"能讲数据"的来源）

| 实验 | 做法 | 产出 |
|------|------|------|
| **索引优化** | 拿苍穹外卖的 `orders`/`order_detail`，跑 `ordersStatistics` 那类统计 SQL 的 explain | 加联合索引前后耗时对比 |
| **深分页** | 用黑马点评/商城的列表接口，构造 `LIMIT 1000000, 10` | 改成"游标分页"后的耗时对比 |
| **锁验证** | 开两个会话验证间隙锁：RR 下 `WHERE id BETWEEN 6 AND 9` 的插入阻塞 | 截图 + 笔记（面试能讲） |
| **MVCC 验证** | 两个会话分别按 RC/RR 隔离级别跑同一组 SELECT | RC 能看到新数据、RR 看不到的截图 |
| **慢查询排查** | 打开慢查询日志（`long_query_time=1`），跑几个接口 | 慢 SQL 清单 + 优化记录 |

> 🎯 这 5 个实验做完，你的简历就能写：**"对核心业务 SQL 做 explain 分析与索引优化，接口 P99 从 X ms 降到 Y ms"**。

## 9. 常见误区（别踩）

1. **从头看到尾**：存储过程/触发器/视图占了 **3.65 h**，面试权重却是全篇最低 → 只看不敲
2. **学 MyCat**：4.93 h 的过时内容 → 换 ShardingSphere（4 h）
3. **只背 explain 的字段含义**：要在**自己项目的真实 SQL** 上跑，否则面试官追问"你优化过哪条"就哑了
4. **跳过 MVCC**：这是 MySQL 面试的"分水岭问题"，也是**唯一能把 RC/RR 讲出原理**的地方
5. **等到 1 月才学**：11 月投实习就要用；索引 + 锁 + MVCC 必须提前（第 5 节阶段 A）
6. **不碰运维篇**：binlog 是主从复制/Canal/数据恢复的地基，**只花 20 分钟但价值极高**
