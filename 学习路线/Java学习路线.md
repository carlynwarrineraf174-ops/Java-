### 8.4 刷题方法论

**每道题的流程：**
1. 自己独立思考 **15-20 分钟**（想不出思路也要想）
2. 想不出来 → 看题解，理解思路
3. 关掉题解，**自己从头写一遍**（不要抄）
4. 写完后对比题解，优化代码
5. 用 Markdown 记录：题目链接、思路、踩坑点

**重要原则：**
- **题量不是目的，掌握了才是**：一题多写几遍胜过刷十题记不住
- **分类刷**：按模块集中刷 8-15 题，形成肌肉记忆
- **错题要复刷**：标记错题，一周后重做，做对了才叫会了
- **简单:中等:困难 ≈ 3:6:1**，主力在中等题
- 面试看重：**代码规范 > 边界处理 > 时间空间复杂度 > 最优解**

### 8.5 平时的每日节奏（学期中版）

```
工作日（有课）：晚上 1.5h 课程（Spring Cloud / JUC / JVM）
               → 睡前 30-40min 刷 1 道力扣（第 1 道先复习昨天的错题）
周末（大块时间）：上午 2-3h 跟敲课程 demo
               下午 1.5h 刷 2 道力扣（按模块顺序）
               晚上 1h 整理笔记（Markdown）
```

### 8.6 算法竞赛题 vs 面试题

| 维度 | 竞赛题（蓝桥杯/洛谷） | 面试题（力扣） |
|------|----------------------|---------------|
| 重点 | 找最优解、数学技巧 | 思路清晰、代码规范 |
| 复杂度 | O(n²) 可能被卡常 | O(n²) 通常可接受 |
| 代码量 | 可能很长（模拟题） | 一般 20-50 行 |
| 边界 | 极端数据考验算法 | 空值、越界等常规边界 |
| 语言 | C++ | **C++**（思路能用 Java 术语讲清即可） |
| 风格 | IO 读入 + 输出 | 函数式编程（写一个方法） |

**所以**：不用纠结"面试题不够难"，面试就不考难题；把力扣 HOT 100 + 剑指 Offer 刷透就够用。
