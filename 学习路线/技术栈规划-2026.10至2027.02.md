## 0.5 关于「先学 AI 还是先学八股」（2026.09.26 补充决策）

> **背景**：有学长建议"先学 Spring AI + 微服务项目 + Python + 大模型 + Agent 项目，全部学完再学 JUC/JVM"。
> **结论**：**方向认同，顺序不认同** —— 你不需要二选一，因为你的容量够（855 h vs 三条线 645 h）。最终方案 = **双线并行 + 项目驱动**。

### 学长对在哪

| 观点 | 判断 |
|------|------|
| AI / 大模型 / Agent 是增量市场，值得早投入 | ✅ 同意（后端岗收缩、AI 岗扩张，JD 开始点名 Spring AI） |
| 项目比八股更能过简历关 | ✅ 同意（大二投实习，**简历关是最难的一关**） |
| 需要学 Python | ✅ 同意（大模型生态 Python 优先） |
| **"先学完 AI 再学 JUC/JVM"** | ⚠️ **只对"已决定转 AI 岗"的人成立** |

### 把 JUC/JVM 压到最后的三个风险

1. **面试时间线不匹配**：2 月就要投递 + 面试，1–2 月才学 JUC/JVM = 边学边面；AQS / 锁升级 / GC 需要读源码 + 画图 + 手写沉淀，不是两周能背出来的。
2. **AI 岗本身也考这些**：Agent 的工程实现就是**并发 + 异步 + 限流 + 缓存**（并行调模型、控 token 成本、会话缓存、长任务队列）。没有 JUC 基础，Agent 项目只能做成 demo，讲不出性能。
3. **八股的"第二层追问"**：背过的和用过的，一句追问就分开。"我学过线程池" vs "我在 Agent 项目里用线程池控并发、用 CompletableFuture 并行调 3 个模型把 RT 从 2.4 s 降到 0.9 s"。

### 解法：项目驱动学八股（直击"学了会忘"这个真问题）

| 项目里做的事 | 反查的知识 | 效果 |
|------------|-----------|------|
| Agent 并行调多个模型 | 线程池参数 / CompletableFuture / 拒绝策略 | 八股变成经验，不衰减 |
| 会话与向量检索缓存 | Redis 缓存三兄弟 / 一致性 | 复用已有 Redis 笔记 |
| 长任务异步 + 进度推送 | 阻塞队列 / WebSocket / 线程池 | 呼应苍穹外卖 |
| 高并发压测 | 锁 / CAS / JMM | 呼应黑马点评秒杀 |

### 什么情况下**完全按学长的顺序**走

**只有一种**：你已决定**转 AI 岗**、不投 Java 后端。
那时 JUC/JVM 降级为"能聊即可"，主语言转 Python，重点变成 Python 工程化 → LangChain/LlamaIndex → RAG → Agent → 部署（FastAPI + vLLM）。
但要接受：**AI 应用岗竞争已经很激烈**（培训班 + 非科班涌入），不少岗位要求硕士/论文。**"Java 后端 + AI 能力"是双保险，"纯 AI"是单点押注。**

### 判断建议质量的方法（元技能）

学长这条建议值多少分，取决于**他的信息来源**：
- 刚拿到 AI 相关实习/offer 且目标岗位与你一致 → 权重高
- 他自己也在摸索/准备转行 → 权重低（和你一样是推测）
- **反问一句**："学长你现在是什么岗位？面试主要问什么？" —— 这一问能省几个月弯路

### 0.5.5 顺序定稿（二次修订 · 2026.09.26 晚）

> **你定下的顺序**：Spring Cloud + **MQ 全量跟完** → Spring AI（~10 h）→ Python 速通 → LangChain/大模型 → **回头学 JUC + JVM** → 投简历。
> **我的结论**：✅ 顺序可行（855 h 排得下串行），但**必须钉三个 deadline**，否则会挤掉三块必考内容。

**修正 1：Python 速通放到 Spring AI 之前（1~2 天，别拖）**
你计划"Spring AI → Python → LangChain"，建议改成 **Python 速通（5~8 h）→ Spring AI → LangChain**：
- 大模型的核心概念（token / embedding / function calling / RAG）在 **Python 生态里资料最多、最好懂**；先用 Java 框架上手容易变成"只会调 API，不懂原理"
- LangChain 本身就是 Python 的，先过语法后面顺；而且只要 1~2 天，不阻塞 Spring AI

**修正 2：JUC 最晚 11 月中启动（改串行为并行），12 月必须收尾**

| 项 | deadline | 理由 |
|----|---------|------|
| JUC（58 h） | **11 月中启动 → 12 月收尾**（副线 1.5 h/天，别等 AI 全学完） | 若 12 月才开始，JUC + JVM 会一路挤到 1 月，直接压掉 MySQL / 计网 / OS |
| JVM（45 h） | **12 月内完成** | 同上；且 JVM 是 MySQL / Redis 性能调优的基础 |

> 这不是反对你的顺序，而是"**串行改并行**"：白天 AI 项目，晚上 1.5 h JUC —— 两条线互相反哺
> （Agent 的并发调用 → 反查线程池/CompletableFuture；会话缓存 → 反查 Redis）。

**修正 3：MySQL 深入 + 计网 + OS 不能消失（1 月寒假）**
你这次只提了"JUC/JVM 巩固基础"，但这三块 **复现率 90%**，而且你**从没系统学过**：
- **MySQL 深入（40 h）**：索引 / MVCC / 锁 / explain / 慢查询 —— 必问，且能变成项目优化数据
- **计算机网络（35 h）+ 操作系统（35 h）**：大厂必考，寒假集中学正好

**其余照你的意思调整**
- ✅ **MQ 全量跟完**（约 25 h 含跟敲）—— 支持，理由见 `spring cloud\微服务学习路线.md` 第 3 节
- ✅ **ES 改为三级方案**（一级 40 min 必看 → 二级 1.5 h 视频 + 4 h 跟敲 → 三级项目需要时）—— **ES 必须挂在项目上才有价值**，孤立学记不住

### 0.5.7 决策留档：为什么是「A · Java 主线 + AI 副线」，而不是「B · AI 先行」（2026.10.04）

> **问题**：先把 Java 技术栈（JUC / JVM / MySQL 进阶 / 深入 Spring）搞定再学 Python + 大模型做 Agent，还是反过来？
> **结论**：**选 A，但要改造 A —— Java 是主线；「先」指的是「先拿到面试门票」，不是「全部学完再碰 AI」。**

**① 三条依据**

| # | 依据 | 说明 |
|---|---|---|
| 1 | **投递倒计时** | 11 月投日常实习、2 月投暑期实习。面试问题占比里 Java 侧占绝大多数（JUC 20 / 项目 20 / Java 基础 15 / MySQL 15 / JVM 10 / Spring 10），**AI 在八股里占 0**（只在项目和简历里得分）→ **离 deadline 近的先做** |
| 2 | **依赖关系** | Agent 做深**需要** JUC（并行调模型 / 超时 / 限流 / 异步任务队列）。先 Java 后 AI → Agent 自带工程含量；先 AI 后 Java → Agent 只能做成 demo，学完 JUC 还得回头重做 |
| 3 | **沉没成本** | 已有 ≈1100 h Java 积累（SSM / Boot / Redis / 微服务 / 苍穹外卖 / 黑马点评 / 93 题）。转纯 AI = 作废这些，且纯 AI 岗竞争更激烈（不少要硕士 / 论文）。**「Java 后端 + AI」是双保险，「纯 AI」是单点押注** |

**② B 的三个具体问题**

1. **时间**：B 会让 Java 基础栈（JUC 58 + JVM 45 + MySQL 40 + Spring 34 ≈ 177 h）压到 12 月才开始，同时还要吃算法 155 h + 八股复习 85 h + 投递 → 必然砍 MySQL / OS，或变成「边面边学」；
2. **项目质量**：还没学 JUC 时做的 Agent，面试官一句「一次调几个模型？超时怎么处理？限流了吗？」就崩 → **等于白做**；
3. **面试**：11 月投日常实习时 JUC 还没上手，而并发是 Java 面试开场必问。

**③ A 的三个约束（缺一条，A 就会退化成「永远不学 AI」）**

1. **AI 入门 30 h 必须在 10 月内做完**（Python 速通 8 h + Spring AI 收尾 + 大模型视频，每天固定 1 h，不占主线）→ 保证 11 月投递时简历上有 AI 标签；
2. **11 月做 T1 + T2**（自有项目 Tool Calling + 知识库 RAG，≈12 h）→ 投产比最高的 AI 动作，直接进简历；
3. **Agent 项目放 12 月**（那时 JUC 已启动 / 收尾）→ 项目天然带并发、限流、缓存，**能讲性能数字**。

**④ 唯一该选 B 的情况**：已决定转**纯 AI 应用岗**、不投 Java 后端。

**⑤ 当前实际状态**：MQ 全量 + Spring Cloud 收尾 + Spring AI 都在跑 —— **已经在「并行」里了；选 B 反而要中断已起步的 Java 线。**

### 0.5.8 四次修订：串行版定稿（2026.10.04）

> **结论**：**支持串行** —— 对 JUC / JVM 这种要读源码、画图、手写的内容，串行的上下文切换成本最低，比并行更容易做深。

### 6.1 ZooKeeper / Dubbo 怎么处理（2026.09.26 追加）

> **结论：现在都不系统学；各花 3~5 h 做"面试版"，时机 = 1 月看目标 JD 之后。**

| 维度 | ZooKeeper | Dubbo |
|------|-----------|-------|
| 面试命中率 | 中等偏低（Spring Cloud Alibaba 用 **Nacos** 替代了它） | **阿里系高频**（SPI/暴露引用/集群容错），其他公司问得少 |
| 你已有的替代品 | **Nacos**（注册中心+配置中心）→ "为什么用 Nacos 不用 ZK" 10 分钟能准备 | **OpenFeign**（HTTP 调用）+ 第 9 节的**手写 RPC** 加练项 |
| 系统学成本 | 15~20 h（ZAB/选举/Watcher/集群运维） | 20~25 h（SPI/服务暴露引用/Netty/容错/泛化） |
| 该花多少 | **面试版 5 h** | **面试版 3~5 h**；**若冲阿里系 → 12~15 h（含 SPI）** |

**核心判断**：面试考的不是 API，而是两个"代表" ——
- **ZK = 分布式协调的代表**（对比 Nacos 的 CP/AP、对比 Redis 锁的 AP）
- **Dubbo = RPC 的代表**（对比 OpenFeign 的 HTTP vs 二进制协议）

→ 所以你要的是 **6~10 张问答卡，不是两门课**。

**ZK 面试版（5 h）**：① znode 数据模型 + 四种节点（**临时顺序节点**）② **ZAB 协议**（半数 ACK、崩溃恢复选主、为什么 2n+1）
③ Watcher 机制（一次性、串行、局限）④ **临时顺序节点实现分布式锁**（对比 Redis 锁）⑤ 谁在用（Dubbo 注册中心、老版 Kafka、HBase）

> 💡 **你已经有一半**：`Redis\Redis学习笔记.md` 的 **Q8「Redis 分布式锁 vs ZooKeeper 分布式锁」** 已有对比表，只需补 ZK 侧实现细节。

**Dubbo 面试版（3~5 h）**：① 架构（Provider/Consumer/Registry/Monitor）+ 调用链路 ② **和 OpenFeign 对比**（二进制 RPC vs HTTP、性能、序列化、治理能力）
③ 负载均衡 + 集群容错（Failover/Failfast/Failsafe/Forking/Broadcast）④ 注册中心（ZK/Nacos，Dubbo 3 改**应用级注册**）⑤ Triple 协议（HTTP/2，兼容 gRPC）
**阿里系加练（+10 h）**：SPI 机制（自适应扩展/Activate）、服务暴露与引用全流程、泛化调用。

**时机与触发条件**

| 情况 | 动作 |
|------|------|
| 1 月看 JD 后 | JD 写 Dubbo → 12~15 h（含 SPI）；写 ZK → 5 h；**都没写 → 各 3 张对比卡，不占主线** |
| 目标阿里系 | Dubbo 提前到 12 月，优先级调到与 MySQL 同档 |
| 其他公司 | 只做问答卡，**不占用主线时间** |

**❌ 明确不建议**：现在（10~11 月）花 30~40 h 系统学 → 会挤掉 MySQL A 段或 JUC；学 ZK 运维（集群/四字命令）；学 Dubbo 源码级（除非冲阿里系）。

## 10. 学习方法（从 SOP 合并 —— 决定"学得值不值"）

> 详细版在 `学习方法与面试呈现SOP.md`，这里放**必须记住的骨架**。

### 10.1 面试价值公式

```
面试价值 = 命中率 × 深度 × 可验证性 ÷ 学习成本
```
| 变量 | 怎么提高 |
|------|---------|
| 命中率 | 只学高频（JUC ~20% / 项目 ~20% / Java 基础 ~15% / MySQL ~15% / JVM ~10% / Redis ~10% / 框架 ~10% / 计网 OS ~10%） |
| 深度 | **能画图 + 能讲坑**即可，**不必读完全部源码**（AQS 只读 `acquire`、Spring 只读 `getBean` + 三级缓存、MyBatis 只读 `MapperProxy`） |
| 可验证性 | 每块交 5 件产出物（见下） |
| 学习成本 | 三遍法 + 止损线 |

### 10.2 【最重要】每块技术栈的标准交付物（5 件，缺一不算学完）

```
① 一张手画原理图（存 notes\，面试前翻图复习，10 分钟顶 2 小时）
② 一个自己敲的 demo（进 GitHub）
③ 10 张面试问答卡  ← 核心机制：到 2 月攒够 150+ 张，面试就是开卷考
④ 一篇博客（讲人话 + 图 + 一个坑）
⑤ 一句简历话术（技术 + 动作 + 量化结果）
```

**问答卡模板（每张三段）**
```
Q：线程池核心线程数怎么设置？
① 一句话（10 秒）：CPU 密集 N+1，IO 密集 2N，真实值靠压测 + 监控动态调
② 30 秒展开：为什么 N+1 / 为什么 IO 密集能远超核数 / 上下文切换成本
③ 追问预备：你们项目怎么设的？满了会怎样？为什么禁用 Executors？
④ 我项目里的例子：Agent 项目并行调 3 个模型，核心 16 + 队列 200 + CallerRuns，RT 2.4s → 0.9s  ← 这段才区分"背过的"和"用过的"
⑤ 坑：一开始用 AbortPolicy，压测直接丢任务…
```

### 10.3 三遍法 + 止损线

| 遍数 | 目标 | 占比 | 交付 |
|------|------|------|------|
| 1 | 能用 | 50% | demo 跑通 |
| 2 | 能讲 | 30% | 原理图 + 10 张卡 |
| 3 | 顶住追问 | 20% | 只读"面试必问的那条源码链路" |

**止损线**：任何一块**超出预算 1.5 倍仍无产出卡片 → 立刻停**，记进"待深挖"，继续往下走。
**判断标准**：这个细节能不能变成"面试官会追问的问题"？不能 → 不读。

### 10.4 问题驱动（解决"学了会忘"）

**每学一块，先在项目里制造一个"没有它会痛"的场景**：

| 要学的 | 先制造的问题 | 学完变成 |
|--------|------------|---------|
| 线程池 | 让接口串行调 3 个服务，RT 2.4 s | 并行化 → RT 0.9 s（有数据） |
| 锁 / AQS | 秒杀超卖 | 乐观锁 + 分布式锁（有对比） |
| JVM / GC | 压测把堆调小触发 Full GC | 会看 GC 日志、会调参 |
| MySQL 索引 | 没索引的分页查询 800 ms | explain + 加索引 → 60 ms |
| Redis 缓存 | 缓存穿透/击穿 | 空值缓存 + 逻辑过期（有代码） |

### 10.5 面试呈现 4 招

| 招 | 做法 | 例 |
|----|------|-----|
| **简历跟事实** | 每个技术名词后跟可验证结果 | ❌"熟悉 Redis" → ✅"Redis + Lua 做秒杀原子判断 + Stream 异步下单，RT 800ms→40ms，QPS 300→3000" |
| **三层答案** | 一句话 → 30 秒展开 → 追问细节 | 分布式锁：SETNX+过期+标识+Lua → 三代演进 → 主从丢锁/RedLock 争议 |
| **主动抛钩子** | 回答里埋"这里我踩过坑/做过取舍" | "我用乐观锁因为冲突率低，压测对比过" → 面试官必问压测细节，那是你的主场 |
| **踩坑故事** | 每项目备 2 个，按「现象→排查→根因→修复→预防」讲 | 别人答"配环境弄了很久"，你答"支付回调 ThreadLocal 为空，因为回调不走登录拦截器…" |

## 12. 给未来 6 个月的 10 条建议（按优先级排序，2026.09.26）

> 这是对本规划的"元建议"——**如果只看一条，看第 1 条。**

### 🥇 第 1 条：信号 > 知识。这周就做"可验证信号"，11 月就投实习

你自学 20 个月，**全部是输入型学习**（课程 + 跟做 + 笔记），从未进入真实反馈回路：没投过简历、没面过试、没被 code review 过。
而**双非 + 无信号的简历，在 HR 手里 3 秒被刷** —— 你的知识早已够支撑第一次面试（中小厂/远程/日常实习），缺的是"被真实检验"。

**这周就能做的 3 件事**：
1. 把三个仓库整理推上 GitHub（`LeetCode\` 已经很规范、`Redis\hm-dianping`、苍穹外卖手册 + 源码笔记）→ 每个配一份像样的 README
2. 用现成素材写 1 篇博客（推荐首篇：*"苍穹外卖支付回调的三个坑"* 或 *"手画 AQS 流程图"*）
3. 上牛客/Boss 直聘看 20 个 Java 实习 JD，逐条对照自己 → 输出一份"缺口清单"（这比任何路线都准）

### 🥈 第 2 条：停止横向扩张，先给已有技术栈做一次"纵向验收"

20 个月学完约 12 个技术栈 ≈ 平均 3-4 周/个 —— **大概率是"跟着课程跑通"的水平，不是"能顶住追问"的水平**。
证据：我在你苍穹外卖的项目里核出支付回调 NPE、拦截器没 `remove`、Redis 只配 key 序列化三个问题 —— 说明跟着敲时缺少批判性审视。

**动作**：花 1 周，用 `学习方法与面试呈现SOP.md` 的 5 件交付物测 4 块：**Spring / MyBatis / Spring Cloud / Redis**。
预计 Spring 和微服务只能讲第一层 → 立刻补问答卡。**面试挂的原因从来不是"没学过"，而是"学过但答不出第二层"。**

### 🥉 第 3 条：项目必须有数据，压测优先级高于再学一个技术栈

你现在的 3 个项目**都没有量化数据**（苍穹外卖没用过 JMeter、黑马点评没有压测报告）。
**12 月的"高并发改造 + 压测"是你未来 6 个月最值钱的动作** —— 它把"学生项目"变成"能讲数据的项目"。
> 面试官问"你的项目 QPS 多少、怎么优化的"——有数据的人和没数据的人，是两个层次。

### 4. 考研岔路口，**12 月前给自己一个截止日期**

你每天 6 h 学技术 = 已默认走"就业路线"。但 AI 算法/研究岗要硕士，双非本科校招定级吃亏。
**判断方法**：① 专业排名能否保研？② 目标岗位要不要硕士？③ 家里需不需要你早点赚钱？
**因为大三下开始分叉** —— 现在决定成本最低。

### 5. AI 项目必须"绑工程"，别做成调 API 的玩具

面试官会问："这和直接调 OpenAI 有什么区别？"
**把并发（并行调模型）、缓存（会话/检索）、限流（控 token 成本）、可观测（耗时/成本核算）做进去** ——
让项目本身证明你是"懂工程的 AI 开发者"，而不是"会调 API 的人"。

### 6. 手撕代码：核心题用 Java 再写一遍（20–30 题）

笔试用 C++ 没问题，但**手撕环节面试官是 Java 岗**，用 C++ 会让人质疑"你是不是 Java 工程师"。
10–11 月起：**思路继续 C++ 练，重点题（HOT100 核心 30 题）用 Java 二刷**。

### 7. 规划打 8 折，并预留两个考试周

6 h/天是理想值 —— 有课、实验、期末。**11 月中和 1 月初各留 2 周几乎零产出**（期末考）。
按 690 h 而不是 855 h 排计划，否则计划一崩就容易自我否定。

### 8. 把"讲义 + 手册"双文件模式推广到每个技术栈

你 Redis（5208 行笔记 + 34 题）和苍穹外卖（讲义 + 面试手册）已经这么做了。
**JUC / JVM / MySQL 也照做** —— 否则面试前 3 天翻不动 5000 行笔记。

### 9. 每周固定一个"输出日"（周日）

画图 + 写卡 + 发博客。**没有输出日的学习周 = 没学**（这是 SOP 里"输入:输出 = 7:3"的落地方式）。

### 10. 练"讲"的能力，别只练"写"的能力

你的笔记水平已经证明"写"很强；但面试是**口头表达考试**。
每周 1 次出声复述（30 问抽 5 张卡）、每月 1 次录音模拟面试。另外：**每天 6 h 久坐 + 熬夜会直接毁掉面试状态**，每周留 1 天减量 + 运动。
